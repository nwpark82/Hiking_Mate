# 등산로 데이터 검증 도구 - 기획/설계 문서

## 1. 프로젝트 개요

### 1.1 목적
- 등산로 GPS 경로 데이터의 출발점/도착점 유효성 검증
- 경로 데이터 자동 보정 및 품질 관리
- 로컬 환경에서 빠르고 직관적인 데이터 검수 작업 지원

### 1.2 핵심 요구사항
- ✅ 로컬 실행으로 빠른 처리 속도
- ✅ 직관적인 UI/UX
- ✅ 단계별 작업 흐름 지원
- ✅ 선택적 지도 연동 (성능 고려)
- ✅ 자동 데이터 분류 및 저장

## 2. 기능 명세

### 2.1 핵심 기능

#### F1. 등산로 데이터 로딩 및 선택
**설명:** 전체 등산로 경로 데이터를 로드하고 작업할 등산로를 선택
- 입력: JSON/GeoJSON 형식의 등산로 데이터 폴더
- 출력: 등산로 목록 (이름, ID, 좌표 개수, 총 거리)
- 필터링: 이름 검색, 정렬 (이름순, 거리순)

**데이터 구조 예시:**
```json
{
  "trail_id": "MT001",
  "name": "북한산 백운대 코스",
  "coordinates": [
    {"lat": 37.123, "lng": 126.456, "alt": 100},
    ...
  ],
  "waypoints": [
    {"type": "start", "name": "우이동 입구", "index": 0},
    {"type": "end", "name": "백운대 정상", "index": 145}
  ]
}
```

#### F2. 출발점/도착점 검증 및 수정
**설명:** 경로의 시작점과 끝점의 유효성을 확인하고 필요시 수정

**검증 항목:**
- 출발점과 도착점 거리 (너무 가까우면 경고)
- 고도 변화 (비정상적인 고도 변화 감지)
- 웨이포인트 정보와의 일치성

**수정 기능:**
- 출발점 ↔ 도착점 스왑 (한 번 클릭)
- 경로 방향 전체 반전 (coordinates 배열 reverse)
- 수동 지점 선택 (리스트에서 특정 인덱스 선택)

**UI 구성:**
```
┌─────────────────────────────────────┐
│ 출발점: 우이동 입구 (index: 0)      │
│ 좌표: 37.123, 126.456 (alt: 100m)  │
│ [도착점으로 변경] [수동 선택]       │
└─────────────────────────────────────┘
┌─────────────────────────────────────┐
│ 도착점: 백운대 정상 (index: 145)    │
│ 좌표: 37.234, 126.567 (alt: 836m)  │
│ [출발점으로 변경] [수동 선택]       │
└─────────────────────────────────────┘
```

#### F3. 갭(Gap) 자동 생성
**설명:** 출발점/도착점 변경 시 발생하는 경로 갭을 자동으로 채움

**알고리즘:**
1. 변경된 지점과 이전 경로 사이의 갭 감지
2. 갭이 발생한 구간의 거리 계산
3. 해당 등산로의 다른 경로 데이터에서 유사 구간 탐색
4. 유사 구간의 GPS 포인트를 가져와 갭 채우기
5. 보간(interpolation) 적용하여 자연스러운 경로 생성

**갭 생성 전략:**
- **전략 1:** 직선 보간 (Linear Interpolation)
  - 가장 빠르지만 자연스럽지 않을 수 있음
  - 거리가 짧을 때(< 50m) 적용
  
- **전략 2:** 경로 데이터 참조
  - 같은 산/지역의 다른 경로 데이터 참조
  - 유사 구간 좌표 복사 및 보정
  
- **전략 3:** 수동 확인 플래그
  - 갭이 너무 크거나(> 200m) 복잡한 경우
  - 사용자가 직접 확인하도록 표시

**UI 표시:**
```
⚠️ 갭 감지: 출발점 변경으로 23개 포인트 누락
[자동 생성] [건너뛰기] [수동 확인]

생성 결과:
✅ 19개 포인트 추가됨 (직선 보간)
📏 갭 거리: 147m
```

#### F4. 경로 길이 검증
**설명:** 완성된 경로와 원본 경로의 길이를 비교하여 유효성 검증

**검증 로직:**
```
완성된 경로 길이 / 원본 경로 길이 <= 2.5
```

**검증 결과:**
- ✅ **통과:** 비율 2.5 이하 → 정제 완료 폴더로 저장
- ❌ **실패:** 비율 2.5 초과 → 실패 데이터 폴더로 저장

**UI 표시:**
```
┌─────────────────────────────────────┐
│ 📊 경로 길이 검증                    │
├─────────────────────────────────────┤
│ 원본 길이:   3.2 km                 │
│ 완성 길이:   3.8 km                 │
│ 비율:        1.19x                  │
│ 상태:        ✅ 통과                │
└─────────────────────────────────────┘
```

#### F5. 카카오맵 연동 (선택적)
**설명:** 필요시 카카오맵에서 경로를 시각적으로 확인

**구현 방식:**
- 기본: 맵 비활성화 (성능 우선)
- 버튼 클릭 시: 맵 로딩 및 경로 표시
- 한 번 로딩 후 캐시하여 재사용

**표시 정보:**
- 전체 경로 폴리라인 (Polyline)
- 출발점 마커 (파란색)
- 도착점 마커 (빨간색)
- 갭 구간 표시 (점선)
- 웨이포인트 마커

**UI 구성:**
```
┌─────────────────────────────────────┐
│ [🗺️ 지도에서 확인하기]              │
│                                      │
│ (버튼 클릭 시 지도 표시)             │
│                                      │
│ [지도 숨기기]                        │
└─────────────────────────────────────┘
```

#### F6. 데이터 분류 및 저장
**설명:** 검증 결과에 따라 자동으로 데이터 분류 및 저장

**폴더 구조:**
```
trail_data/
├── input/              # 원본 데이터
│   └── raw_trails/
├── output/
│   ├── validated/      # 정제 완료
│   │   └── MT001_validated.json
│   ├── failed/         # 검증 실패
│   │   └── MT002_failed.json
│   └── logs/           # 작업 로그
│       └── validation_log.json
```

**저장 데이터:**
```json
{
  "trail_id": "MT001",
  "original_length": 3200,
  "validated_length": 3800,
  "length_ratio": 1.19,
  "modifications": [
    {
      "type": "swap_points",
      "timestamp": "2025-11-25T10:30:00Z"
    },
    {
      "type": "gap_fill",
      "points_added": 19,
      "method": "linear_interpolation"
    }
  ],
  "validated_at": "2025-11-25T10:31:00Z",
  "status": "validated"
}
```

## 3. 시스템 아키텍처

### 3.1 기술 스택

**프론트엔드:**
- HTML5 + CSS3 (간단한 UI)
- JavaScript (ES6+)
- React (선택 - 복잡한 상태 관리 필요시)

**지도 라이브러리:**
- Kakao Maps JavaScript API (선택적 로딩)
- 대안: Leaflet + OpenStreetMap (오프라인 가능)

**데이터 처리:**
- Turf.js (GPS 좌표 계산, 거리 측정)
- Papa Parse (CSV 파싱, 필요시)

**로컬 실행:**
- **옵션 1:** 단순 HTML 파일 (브라우저에서 직접 실행)
  - 장점: 설치 불필요, 가볍고 빠름
  - 단점: 파일 시스템 접근 제한
  
- **옵션 2:** Electron (데스크톱 앱)
  - 장점: 파일 시스템 완전 접근, 네이티브 느낌
  - 단점: 번들 크기 증가

**권장: 옵션 1 (HTML + File API)**
- 로컬 파일을 드래그 앤 드롭으로 로드
- 브라우저에서 JSON 읽기/쓰기
- 수정된 파일 다운로드

### 3.2 데이터 흐름

```
[원본 데이터] 
    ↓ (파일 로드)
[데이터 파싱]
    ↓ (검증)
[출발/도착점 검증] → [수정 필요?] → [수정 UI]
    ↓ (갭 감지)
[갭 자동 생성] → [보간 알고리즘]
    ↓ (길이 계산)
[경로 길이 검증] → [통과/실패]
    ↓ (저장)
[데이터 저장] → [validated/ 또는 failed/]
```

### 3.3 주요 모듈

#### Module 1: TrailLoader
```javascript
class TrailLoader {
  loadFile(file)              // 파일 로드
  parseTrailData(json)        // JSON 파싱
  validateStructure(data)     // 데이터 구조 검증
}
```

#### Module 2: TrailValidator
```javascript
class TrailValidator {
  validateEndpoints(trail)    // 출발/도착점 검증
  swapEndpoints(trail)        // 출발/도착점 스왑
  reverseTrail(trail)         // 경로 방향 반전
}
```

#### Module 3: GapFiller
```javascript
class GapFiller {
  detectGap(trail)            // 갭 감지
  fillGap(start, end, strategy) // 갭 채우기
  linearInterpolation(p1, p2, steps) // 선형 보간
  calculateDistance(p1, p2)   // 거리 계산
}
```

#### Module 4: LengthValidator
```javascript
class LengthValidator {
  calculateLength(coordinates) // 총 거리 계산
  compareLengths(original, modified) // 길이 비교
  validateRatio(ratio)        // 비율 검증 (2.5x)
}
```

#### Module 5: MapController (선택적)
```javascript
class MapController {
  initMap(containerId)        // 지도 초기화
  drawTrail(coordinates)      // 경로 그리기
  addMarkers(start, end)      // 마커 추가
  showGapSection(gapPoints)   // 갭 구간 표시
}
```

#### Module 6: FileExporter
```javascript
class FileExporter {
  exportValidated(trail)      // 검증 완료 파일 저장
  exportFailed(trail, reason) // 실패 파일 저장
  generateLog(actions)        // 로그 생성
}
```

### 4.2 작업 흐름 (Workflow)

```
1. 파일 로드
   ↓
2. 등산로 선택
   ↓
3. 출발/도착점 확인
   ├→ OK → 5단계
   └→ 수정 필요 → 4단계
   ↓
4. 출발/도착점 수정
   ├→ 교환
   ├→ 반전
   └→ 수동 선택
   ↓
5. 갭 확인 및 생성
   ├→ 갭 없음 → 6단계
   └→ 갭 있음 → 자동 생성 → 6단계
   ↓
6. 길이 검증
   ├→ 통과 (≤2.5x) → 7단계
   └→ 실패 (>2.5x) → 실패 폴더 저장
   ↓
7. 검증 완료 저장
   ↓
8. 다음 등산로 (2단계로)
```

### 4.3 단축키

- `Space`: 지도 토글
- `Enter`: 검증 완료
- `Ctrl + S`: 현재 상태 저장
- `Ctrl + Z`: 실행 취소
- `→`: 다음 등산로
- `←`: 이전 등산로

## 5. 성능 최적화

### 5.1 지연 로딩 (Lazy Loading)
- 카카오맵 API: 버튼 클릭 시에만 로드
- 이미지/아이콘: 필요할 때만 로드
- 대용량 경로: 가상 스크롤링 적용

### 5.2 캐싱 전략
- 로드한 등산로 데이터: 메모리 캐시
- 계산된 거리: 캐시 (변경 시에만 재계산)
- 지도 인스턴스: 재사용

### 5.3 배치 처리
- 여러 등산로 한 번에 검증 (자동 모드)
- 백그라운드에서 처리하고 결과만 표시

## 9. 확장 가능성
